Galaxy RAG · 企业知识库平台 银河集团｜集团内部知识库

技术栈：Python、FastAPI、LangGraph、MinerU、Milvus、PostgreSQL、MinIO、ranx、bge-m3、bge-reranker-large、deepseek-v4-pro

  • 文档解析与知识组织：基于 MinerU 将 PDF 转换为 Markdown，结合视觉模型生成图片描述；设计覆盖正文、列表、表格和图片的结构化切分，保留标题层级与前向上下文，长表格按行拆分并重复表头，减少材料清单、政策条件等内容切分后的语义缺失。
  • 多路召回与 Reranking：本地链路以 bge-m3 构建 Dense、Sparse 与 HyDE 三路召回，使用 RRF 融合候选结果，通过 bge-reranker-large 完成 Reranking，再结合分差截断与 MMR 筛选上下文，兼顾业务术语匹配、语义相关性与结果多样性，减少相似段落重复占用上下文。
  • 多轮问答与证据追溯：使用 deepseek-v4-pro 完成 Query Understanding，结合会话历史改写查询、补全追问中的指代与条件，并生成用于检索的 HyDE 假设文档；将检索来源纳入回答约束，要求证据不足时明确说明，输出可追溯的文档引用与图片来源，并持久化对话和引用快照，支持刷新后恢复历史。
  • 工作流与模型适配：使用 LangGraph 编排上传、解析、图文增强和向量入库，提供任务阶段、处理进度与失败状态；分离本地 Embedding 与 Reranking、远程查询理解与答案生成的模型职责，并通过并发限制、模型预热和就绪检查提高运行可控性。
  • 评估与持续优化：采用 ranx 评估检索效果，结合 Bad Case 分析迭代切分策略、多路召回与 Reranking 参数。以 300 条业务问答及人工标注的相关文档为评测集，相较仅使用 bge-m3 稠密检索的基线，Recall@10 从约 65% 提升至约 85%，MRR@10 从 0.61 提升至 0.79；固定测试环境下，单并发检索链路 P95 耗时为 1.2 秒（含查询改写、HyDE 与 Reranking，不含最终答案生成）。
  • 企业应用交付：基于 FastAPI、PostgreSQL 与 MinIO 实现登录认证、共享知识库和用户级任务／会话隔离；支持新文档完成向量化后替换旧版本，形成可导入、可更新、可追溯的知识使用流程。累计接入约 3,200 份政策资料、产品手册、业务流程及培训文档，构建约 2.6 万个可检索知识片段，覆盖身份规划、房产服务、教育规划与企业服务等业务线。
